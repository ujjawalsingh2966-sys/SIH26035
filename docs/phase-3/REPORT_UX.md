# Report Generation UX

The report interface translates verified abstract metrics into structured historical documents. 

## 1. Zero-Edit Preview Modals
A technician or reviewer opening a Report Preview enters a strict visual artifact mirroring the Phase 1 OIML output requirements conceptually. 
* All inputs are rendered exactly as evaluated by the Core Engine. 
* Any UI components (buttons, links) are suppressed structurally during generation.

## 2. Version Footprints
PDF reports (or static HTML views) natively stamp the immutable `RULE_VERSION_ID` alongside digital signatures verifying absolute traceability, ensuring an audit happening 5 years post-generation anchors perfectly to mathematical histories.

## 3. History Management
The UI presents specific Document Revision histories distinguishing between canonical sealed reports vs preview drafts pulled natively mid-test by curious technicians.

## 4. Pending / TBD States
If official formatting is undefined during architecture, a generic Data Table representation binds seamlessly to the output UI preventing arbitrary lock-in.
